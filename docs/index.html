FOKEN

Proof-of-contribution valuation gate

A coarse, deterministic pre-filter in front of the binding governance decision. An invoice goes in; a verdict comes out — PASS, FAIL, or REVIEW. Nothing is minted, priced, or transferred here.

The binding decision is always the human >50% vote. The formula is a pre-filter only — it never overrides the vote, and a PASS does not mint anything.

What it is

Foken is the off-chain half of the Foken governance design: a verifiable contribution pre-filter, not equity minting. A contributor submits a Foken Invoice — a JSON document describing the work, its provenance, and its IP assignment. The gate validates it against hard gates, applies the net-utility formula, and emits a verdict. There is no blockchain, no token economics, no secrets, and no deployment.

PASS

Net utility positive — eligible for the human vote.

FAIL

Malformed, unsigned, unprovenanced, or net-negative. Rejected outright.

REVIEW

Fixable by a human: missing numbers, or a valuation that deviates from history.

Precedence is FAIL > REVIEW > PASS — a net-negative invoice never reaches an extra review round.

The net-utility formula

net = futureWorkAvoidedHours − (workAddedHours + 1.5 × maintenanceDebtHours)

The 1.5 weight reflects that maintenance debt is worse than work added: it recurs. The netUtility inputs are tool-computed — the gate takes them as given and does not re-derive them from a repo.

Verdict logic, in precedence order

StepCheckResult
1Structure — missing or type-broken required fieldsFAIL
2Hard gates — signed IRREVOCABLE ASSIGNMENT, sha256:// provenance, valid 0x contributor, positive integer self-assessmentFAIL
3netUtility present and non-negativeelse REVIEW
4Net-utility formula — net ≤ 0FAIL
5Valuation deviation (>2× median of last 10 history invoices, with --history)REVIEW
6net > 0PASS

Run it

uv run python gate.py invoice.json          # verdict as one JSON line
python3 gate.py -                          # '-' reads stdin
python3 gate.py invoice.json --history history.json
python3 gate.py invoice.json --human       # pretty table

# reviewer set + off-chain tally
python3 tally.py --reviewers reviewers.json --votes votes.json
python3 tally.py --reviewers reviewers.json --votes votes.json \
  --review-round 2 --min-approvals 4

Exit codes: 0 = PASS, 1 = FAIL, 2 = REVIEW. Stdlib only — Python 3.11+, no third-party dependencies.

Reviewer set & quorum

Consensus holds when strictly more than half of the reviewer set approves — 3 of 6 is exactly 50% and does not quorum. When k is met, tally.py emits the mint-ready payload matching the on-chain AttestationVerifier.mintFromConsensus input. Signatures are format-checked only; real verification is out of scope for this prototype.
